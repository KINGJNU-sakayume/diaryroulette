# 일기 룰렛

매일 룰렛이 정해 주는 방식으로 쓰는 일기 앱입니다. 미션을 한 번 뽑으면 그날 하루 동안 바뀌지 않고,
한 번 나온 미션은 7일 동안 쉬었다가 다시 나옵니다. 모든 기록은 이 기기의 브라우저(IndexedDB)에만 저장됩니다.

## 작성 방식

- **글쓰기** — 규칙이 있는 미션은 어긋난 부분에 밑줄이 그어집니다. 명사·꾸밈말 판별처럼 형태소 분석이 필요한
  규칙은 짐작이라서 화면에도 그렇게 안내합니다. 글자 수 조건은 이모지를 한 글자로 셉니다.
- **타이머** — 첫 글자를 쓰면 시작하고 끝나면 더 쓸 수 없습니다. 중간에 나갔다 와도 남은 시간부터 이어집니다.
- **지우기 금지 / 보이지 않게 쓰기** — 모바일 가상 키보드의 삭제까지 막고, 한글 조합 중 수정은 허용합니다.
- **그리기** — 자유 그리기, 몸 윤곽 밑그림, 도형만, 한 가지 색의 농담, 감정 온도 원 찍기. 되돌리기를 지원하고
  그림은 테마와 상관없이 같은 종이색 위에 저장됩니다.
- **이모지** — 이모지·띄어쓰기·줄바꿈만 입력됩니다(숫자·기호 단독은 걸러 냄).
- **쓰고 파쇄** — 내용은 저장하지 않고 "썼다"는 기록만 남깁니다.
- **칸 채우기(양식)** — 칸마다 따로 쓰고, 모든 칸을 채우면 완료할 수 있습니다.

새벽 2시 전까지는 전날 일기로 칩니다. 쓰는 중에는 4초마다, 그리고 화면을 떠날 때 자동 저장됩니다.

## Life Hub 연결 (선택)

통계 → **Life Hub**에서 연결하면 Claude 대화에서 오늘의 미션 룰렛을 돌릴 수 있어요.

- 앱은 미션 목록(id·제목·카테고리)과 오늘 상태(쉬는 미션, 오늘 이미 정한 미션)만 Life Hub에 공유해요. **일기 내용은 보내지 않아요.**
- Life Hub는 공유된 목록 안에서만 뽑고, 그날 이미 정한 미션이 있으면 새로 뽑지 않아요. 같은 날 다시 물어도 같은 미션이에요.
- Claude 카드에서 「일기 쓰기」를 누르면 다음에 앱을 열 때 오늘의 미션으로 정해져요(설정 「Claude에서 승인된 항목 자동 반영」, 기본 켜짐). 저장 전에 앱이 날짜·7일 쿨다운·오늘 미션을 다시 확인해요.
- 자동으로 정해지지 않은 제안은 홈 화면에서 「이걸로 할게요」 또는 「거절」로 정해요.
- 연결 코드: `src/integration/lifehub.ts`(OAuth·동기화), `src/integration/boardUpload.ts`(보드 타일 업로드), `src/integration/lifehubApply.ts`(앱 규칙으로 판단·저장), `public/lifehub-client.json`.

## 보드 타일 (Life Board)

[Life Board](https://github.com/KINGJNU-sakayume/board)에 올릴 타일 목록을 만들어 Life Hub에 보냅니다.
보내는 것은 **보드용 목록뿐**이고, 일기 내용과 기록 자체는 올리지 않습니다(미션 제목·날짜·카테고리명만).
모양은 보드가 정하고, 이 저장소는 규격 v1에 맞는 데이터만 만듭니다. 이 앱에는 이미지가 없어 표지·포인트색은 보내지 않습니다.

| id | 타일 | 형태 | 크기 (처음) | 처음부터 보임 | 데이터 출처 |
| --- | --- | --- | --- | --- | --- |
| `today` | 오늘의 미션 | type · line | 2x1, 4x1 (2x1) | 예 | 저장된 오늘의 미션 기록 + 그날 일기의 상태(쓰는 중·완료·아직 안 씀) |
| `streak` | 연속 기록 | type · num | 1x1, 2x1 (1x1) | 아니오 | 완료한 일기 날짜 → `src/lib/streak.ts`의 `computeStreaks` |
| `recent` | 최근 일기 | type · list | 2x1, 2x2, 4x2 (2x2) | 아니오 | 완료한 일기 최근 5개(상세 창은 12개): 미션 제목·날짜·카테고리 |

- 타일 글자는 앱을 다시 열 때까지 보드에 그대로 남으므로 "오늘"·"어제" 대신 날짜를 씁니다. 오늘의 미션 타일의 라벨은 `11/8 미션`처럼 뽑은 날짜이고,
  오늘 미션이 없으면 `아직 뽑지 않았어요`와 마지막 일기 날짜를 보여 줍니다. 연속 기록은 `11/7까지`처럼 마지막으로 센 날을 함께 보냅니다.
  날짜는 일기 기준(새벽 2시 전은 전날)입니다.
- 목록은 `src/lib/boardTiles.ts`의 `buildBoardTiles(state, now)`가 만듭니다. 순수 함수라 같은 입력이면 같은 출력이고, 무작위·네트워크·저장소를 쓰지 않습니다.
  타일 `id`(`today`·`streak`·`recent`)는 보드의 사용자 배치가 이 값으로 저장되므로 바꾸지 않습니다.
- 예시 출력은 [`board/sample.json`](board/sample.json)(지어낸 값)입니다. 테스트가 board의 `js/schema.js` 복사본(`src/__tests__/vendor/board-schema.js`,
  출처 커밋은 파일 맨 위)으로 규격을 검사하고, 예시 파일이 함수 출력과 같은지도 확인합니다.

### 언제, 어느 기기에서 올리나

- `PUT /diaryroulette/v1/board` (스코프 `diaryroulette:board`). 코드는 `src/integration/boardUpload.ts`, 앱이 열려 있는 동안 도는 부분은 `BoardUploadAgent`입니다.
- **설정 → Life Hub → 「이 기기에서 보드에 올리기」(기기별, 기본 꺼짐)** 를 켠 기기에서만 올립니다. 일기는 기기 안에만 있고 Life Hub는 앱마다 최신 목록 하나만 보관하므로,
  여러 기기에서 켜면 마지막에 올린 기기의 목록으로 바뀝니다.
- 타일에 영향을 주는 변화(미션 뽑기, 일기 저장·완료·삭제, 가져오기)가 생기면 올립니다. **10분에 한 번 이하**(마지막 시도 기준)이고, 10분 안이면 시간이 찼을 때
  그 시점의 내용으로 한 번 보냅니다. 앱이 닫힌 사이에 바뀐 것은 다음에 앱을 열 때 마지막 성공 내용(sha256, `generated_at` 제외)과 비교해 다르면 바로 보냅니다.
- 내용이 같으면 보내지 않지만, 마지막 성공이 하루보다 오래됐으면 같아도 한 번 보냅니다(보드의 '오래됨' 14일은 Hub가 받은 시각 기준).
- 올리지 않는 경우: Life Hub에 연결돼 있지 않을 때, 이 기기의 스위치가 꺼져 있을 때, 기록이 하나도 없을 때(새 기기가 빈 목록으로 덮지 않게), 재연결이 필요할 때.
- 응답: `200`(`unchanged`·`ignored` 포함)은 성공. `400`·`413`은 앱 쪽 문제라 같은 내용을 다시 보내지 않고 개발자 콘솔에만 남깁니다(기기 시계가 5분 넘게 빠르면 `400`이 날 수 있음).
  네트워크 오류·`5xx`는 다음 기회에 다시 보냅니다. 업로드 실패는 앱의 다른 기능에 영향을 주지 않습니다.

### 다시 연결이 필요한 경우

보드 권한(`diaryroulette:board`)이 생기기 전에 연결한 기기는 첫 업로드가 `403 insufficient_scope`로 옵니다. 이때 **Life Hub 토큰은 지우지 않고**(수신함·동기화는 그대로),
설정에 「보드에 올리려면 Life Hub에 다시 연결해 주세요」 안내가 뜹니다. 「다시 연결」을 한 번 누르면 새 권한이 포함됩니다. 재연결 전에는 다시 시도하지 않습니다.
(`403`의 `WWW-Authenticate` 헤더를 브라우저가 읽을 수 없는 경우에도 같은 안내로 처리합니다. 그 외의 `403`과 갱신 뒤에도 계속되는 `401`은 기존 규칙대로 연결이 해제됩니다.)

## 개발

```bash
npm install
npm run dev      # 개발 서버 (오른쪽 아래 DEV 버튼으로 점검 패널)
npm test         # 단위 테스트 (vitest)
npm run lint
npm run build    # 타입 검사 + 프로덕션 빌드
npm run preview  # 빌드 결과(dist/)를 로컬에서 확인
npm run icons    # public/favicon.svg로 PWA 아이콘 재생성
```

`main` 브랜치에 push하면 GitHub Pages로 배포됩니다.

### 구조

```
src/
  data/        미션·카테고리·영감 카드 (미션 id는 저장된 일기와 연결되는 영구 키 — 바꾸지 말 것)
  lib/         순수 로직: 규칙 검사(rules), 한글 분해(hangul), 글자 수·이모지(text), 날짜, 연속 기록, 양식
  db/          IndexedDB 접근
  hooks/       오늘의 미션·휴식 목록·포커스 트랩
  components/  에디터(글쓰기·타이머·그리기·이모지·파쇄·칸 채우기), 미션 카드, 공용 UI
  pages/       오늘 · 쓰기 · 기록 · 쓰던 글 · 통계
```

미션을 추가할 때는 `src/data/missions.ts`에 항목을 넣으면 됩니다. 자동 규칙 검사가 필요하면 `check`에
검사기 이름을, 양식이면 `editorType: 'prompts'`와 `prompts` 칸 목록을 지정하세요.
